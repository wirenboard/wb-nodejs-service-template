# wb-nodejs-service-template

Публикует в веб-интерфейсе контроллера устройство со скоростью приема по сети.

*(Он же шаблон Node-сервиса для Wiren Board: как сделать из него свой сервис - во врезке ниже.)*

## Что делает

Показывает в веб-интерфейсе контроллера, сколько данных приходит по сети. На странице
"Устройства" появляется устройство "Сетевой трафик": текущая скорость приема, пик с момента
запуска и время работы самого сервиса. Кнопка сбрасывает пик, когда нужно померить заново.

![Устройство "Сетевой трафик" на странице "Устройства"](docs/images/device.png)

*Скриншоты сняты с интерфейсом на английском, в русском интерфейсе названия переведены.*

Это нужно, чтобы видеть, идет ли обмен по сети вообще и ровно ли он идет. Нуль на приеме -
повод проверить связь, а не ждать жалоб. Пик помогает поймать то, что глазами не застать:
короткий всплеск нагрузки виден и через час, когда скорость давно вернулась к обычной.
На эти значения можно повесить сценарий - например, прислать уведомление при превышении
порога.

Какой интерфейс смотреть и как часто - настраивается в веб-интерфейсе, в разделе
"Настройки" -> "Конфигурационные файлы", карточка "Сетевой трафик". За ней стоит файл
`/etc/wb-nodejs-service-template.conf`, при записи из интерфейса сервис перезапускается сам.
Тот же файл можно править по SSH, но тогда перезапуск за вами:
`systemctl restart wb-nodejs-service-template`. Если интерфейс указан неверно, показатель
помечается ошибкой, а сервис продолжает работать.

![Настройки сервиса в веб-интерфейсе](docs/images/config.png)

Форму рисует confed по схеме из пакета: подписи, подсказки, допустимые значения и перевод
берутся оттуда, руками ее никто не верстает.

> ### Как превратить шаблон в свой сервис (этот раздел потом удалить)
>
> Все внутри этой цитаты относится только к самому шаблону и в вашем сервисе не нужно.
>
> Все для разработчика - в [docs/wb-service-guide.md](docs/wb-service-guide.md): как
> устроен сервис WB, откуда берется версия, как включить git-хуки, прогнать тесты и
> собрать пакет (раздел "Перед контрибьютом"), как устроено пакетирование. Это пояснения
> к шаблону, в готовом сервисе файл не нужен.
>
> 1. Создайте репозиторий кнопкой **Use this template** на GitHub.
> 2. Переименуйте пакет. Авторитетный список мест дает
>    `git grep -l wb-nodejs-service-template`
>    Переименовать надо и сами файлы: обертку в `bin/`, три файла `debian/<имя>.*`,
>    конфиг, схему и скрипт для `/etc/wb-configs.d`.
>    Отдельно проверьте `src/main.js`: там лежат идентификатор устройства и путь к конфигу.
>    Забыть их легче всего, и ломается это молча - пакет соберется, а сервис на контроллере
>    не найдет свой конфиг. Имя в `package.json` тоже меняется, после чего `npm install`
>    перепишет `package-lock.json`.
> 3. Начните `debian/changelog` со своей версии и своего авторства.
> 4. Раскомментируйте вызов сборки в `Jenkinsfile`. В шаблоне он закомментирован намеренно,
>    иначе Jenkins собирал бы сам шаблон и публиковал его в релизный фид.
> 5. Замените заголовок на имя своего пакета, строку под ним и раздел "Что делает" -
>    на описание своего сервиса, а курсивную строчку про шаблон удалите.
> 6. Удалите пояснения к шаблону вместе со скриншотами: `git rm -r docs`
> 7. Удалите этот раздел целиком, от заголовка до конца цитаты.
>
> **Проверить, что ничего не забыли:** `git grep -n wb-nodejs-service-template`
> не должна находить ничего за пределами этого раздела.

## Установка

Скопируйте собранный пакет на контроллер и поставьте:

```bash
sudo apt install ./wb-nodejs-service-template_*.deb
```

Сервис включается и стартует сам, устройство появляется в веб-интерфейсе. Проверить:

```bash
systemctl status wb-nodejs-service-template
```

Если что-то не так, смотреть журнал:

```bash
journalctl -u wb-nodejs-service-template -n 50
```

## Что внутри

| Что | Где |
|---|---|
| Код сервиса | `src/` |

| Тесты | `tests/` |
| Сборка пакета, юнит, скрипты установки | `debian/` |
| Git-хуки репозитория | `hooks/` |
| Конфиг по умолчанию и схема для веб-интерфейса | в корне |
| Пояснения для разработчика и скриншоты для README | `docs/` |
